# DEALS-STORE

DEALS-STORE is a containerized deals and wishlist web application. It includes
a static HTML/CSS/JavaScript frontend, a PHP REST API, a MySQL database, and
DevOps assets for local Docker Compose, Kubernetes, Jenkins CI/CD, monitoring,
Terraform, and Ansible.

Users can browse discounted offers, create an account, sign in, and save or
remove favorite deals from a personal wishlist.

## Features

- Browse available deals from the database.
- Register and log in with email and password.
- Keep the active user in browser local storage.
- Save and remove favorite deals.
- Seed the database with sample offers.
- Run the app locally with Docker Compose behind an Nginx reverse proxy.

## Tech Stack

- Frontend: HTML, CSS, vanilla JavaScript, Nginx
- Backend: PHP 8.3 CLI, PDO MySQL
- Database: MySQL 8.4
- Local orchestration: Docker Compose
- CI/CD: Jenkins
- Deployment assets: Kubernetes, Terraform, Ansible
- Monitoring: Prometheus, Grafana, cAdvisor, Node Exporter

## Environment Variables

Docker Compose reads database and image settings from `.env`. Create it in the
project root:

```bash
DOCKERHUB_USERNAME=your-dockerhub-username
IMAGE_TAG=local
MYSQL_ROOT_PASSWORD=root
MYSQL_DATABASE=deals_store
MYSQL_USER=deals-user
MYSQL_PASSWORD=deals-password
```

The backend reads its database connection from these runtime variables:

- `MYSQL_HOST`
- `MYSQL_DATABASE`
- `MYSQL_USER`
- `MYSQL_PASSWORD`

In Docker Compose, `MYSQL_HOST` is set to `mysql-db`.

## Run Locally

Start the full app stack:

```bash
docker compose up -d --build
```

Open the application:

```text
http://localhost/
```

The reverse proxy routes:

- `/` to the frontend container
- `/api/` to the backend container
- `/healthz` to a simple proxy health check

Stop the stack:

```bash
docker compose down
```

Remove the database volume and start with a fresh database:

```bash
docker compose down -v
```

## Seed Sample Data

After the containers are running, insert demo offers:

```bash
docker compose exec backend php seed.php
```

Test the backend database connection:

```bash
docker compose exec backend php config/test_db.php
```

## API Endpoints

The frontend calls the API through the reverse proxy at `/api`.

| Method | Endpoint | Description |
| --- | --- | --- |
| `POST` | `/api/auth.php` | Register or log in. Send `action` as `register` or `login`. |
| `GET` | `/api/offers.php` | Return all offers. |
| `GET` | `/api/favorites.php?user_id=ID` | Return saved offers for one user. |
| `POST` | `/api/favorites.php` | Add or remove a favorite. Send `action` as `add` or `remove`. |

## Database

The schema lives in `database/schema.sql` and creates:

- `users`: account details and password hashes
- `offers`: deal information, prices, discounts, images, and expiry dates
- `favorites`: saved offers per user

`offers.final_price` is generated by MySQL from `old_price` and
`discount_percentage`.

## Kubernetes

Kubernetes manifests are in `k8s/`.

Apply the stack:

```bash
kubectl apply -f k8s/
```

Useful service routes:

- Frontend NodePort: `30080`
- Backend NodePort: `30081`
- Ingress host: `deals-store.local`

The backend reads database settings from `k8s/configmap.yaml` and
`k8s/secret.yaml`.

## Monitoring

Start the monitoring stack:

```bash
docker compose -f monitoring/docker-compose.monitoring.yml up -d
```

Services:

- Prometheus: `http://localhost:9090`
- Grafana: `http://localhost:3000`
- cAdvisor: `http://localhost:8080`
- Node Exporter: `http://localhost:9100`

## CI/CD

`Jenkinsfile` defines a pipeline that:

- creates `.env` from Jenkins credentials
- validates Docker Compose configuration
- builds frontend, backend, and MySQL images
- tags and pushes images to Docker Hub
- starts the stack and checks the backend API
- records the last successful image tag for rollback

Expected Jenkins credentials:

- `MYSQL_ROOT_PASSWORD`
- `MYSQL_DATABASE`
- `MYSQL_USER`
- `MYSQL_PASSWORD`
- `Docker_Access_Token`

## Infrastructure

Terraform files in `terraform/` define AWS infrastructure including a VPC,
public subnets, EC2 instance, RDS MySQL database, S3 bucket, security groups,
and an Application Load Balancer.

Ansible files in `ansible/` configure a target server and clone/update the
repository on the `devops` branch.

## Important Files

- `docker-compose.yml`: local application services and networks
- `reverse-proxy/nginx.conf`: routes frontend traffic and API traffic
- `backend/config/db.php`: PDO database connection
- `backend/api/auth.php`: register and login endpoint
- `backend/api/offers.php`: offer listing endpoint
- `backend/api/favorites.php`: wishlist endpoints
- `database/schema.sql`: MySQL schema
- `frontend/js/app.js`: frontend API calls and auth/favorites behavior
- `k8s/`: Kubernetes manifests
- `monitoring/prometheus.yml`: Prometheus scrape configuration

## Notes

- `.env` is ignored by Git.
- Database credentials in `.env`, Kubernetes secrets, and Jenkins credentials
  should stay aligned with the target environment.
- The Compose MySQL health check currently uses the root password value `root`;
  update it in `docker-compose.yml` if you change `MYSQL_ROOT_PASSWORD`.
- The frontend uses `const API_BASE = '/api'`, so it expects a reverse proxy or
  matching server route for API requests.
